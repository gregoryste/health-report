# Plano: dar ao n8n as decisões de fluxo (opção 2)

Criado em 14/11/2026. Escolhido pelo Gregory: **opção 2**. Este arquivo é seguido em loop: cada iteração faz **uma** tarefa, verifica, marca e registra.

## Objetivo

Hoje cada fluxo do n8n tem 2 nós (gatilho → uma chamada ao serviço) e o serviço decide tudo por dentro.
Depois deste plano, o **serviço executa as etapas e devolve fatos** (prioridade, tipo da dúvida, status do envio), e **o n8n decide o caminho** com nós IF/Switch visíveis, aciona as ações de cada ramo e trata erros.

Princípios:
- **Nenhuma regra clínica sai do serviço** (regra fixa, LLM, checagens, classificador continuam no Python).
- O n8n decide só o **roteamento**: o que fazer com o resultado (alertar, responder, avisar falha).
- **Plano B continua valendo:** com `ORQUESTRADOR=interno`, o serviço faz o mesmo roteamento em Python, numa tabela única (`ROTAS`). Um teste garante que a tabela do Python e os ramos do n8n são iguais.

## Regras do loop (obrigatórias)

1. **Uma tarefa por iteração:** pegar a primeira `- [ ]` da lista, fazer só ela, verificar pelo critério de pronto, marcar `- [x]` e escrever uma linha no **Registro** (data, hora, o que foi feito, como foi verificado).
2. **Ambiente de teste isolado até a Fase 4:**
   - **não tocar** em `dados/prototipo.db`, `registros/aprovacoes.jsonl`, no volume `n8n_n8n_dados`, no serviço da porta **8000** nem no n8n da porta **5678**;
   - testes usam o serviço de teste na **8001** (cópia do banco, `WHATSAPP_MODO=simulado`) e o n8n de teste na **5679** (volume próprio).
3. **LLM interna:** nenhuma chamada nas Fases 0–3 (testes com a LLM substituída por resposta fixa). Na Fase 4, no máximo **6 chamadas no total**, uma por vez, com pausa de 3 s. Antes de chamar, escrever no Registro quantas serão.
4. **WhatsApp:** nunca `WHATSAPP_MODO=meta` em teste. Nenhuma mensagem real sai durante este plano.
5. **Banco do n8n:** só mexer em fluxo pelos JSON (com `id`) + `import:workflow` + `publish:workflow`. Nunca copiar `database.sqlite` sem os `-wal`/`-shm`.
6. **Segredos:** nunca escrever valores do `.env` em arquivo, log ou mensagem.
7. **Se uma tarefa falhar duas vezes:** marcar `- [!] BLOQUEADO: motivo`, registrar e **parar o loop**, avisando o Gregory.
8. **Ao terminar tudo** (até a 6.10): escrever o resumo final no Registro, avisar o Gregory e parar o loop.
10. **Se a Fase 6 mostrar piora** em qualquer item depois da Fase 4 (ambiente real): não tentar remendar no real. Restaurar o backup da 4.1 (fluxos pelos JSON exportados; serviço com o código anterior), registrar e parar o loop avisando o Gregory.
9. Não apagar arquivos do usuário. Arquivos temporários ficam no scratchpad da sessão.

## Fase 2 · Fluxos com decisões (JSON em `n8n/fluxos/`, sempre com `id`)

- [x] **2.1 Fluxo 1 · Entrada do laudo.** Webhook → HTTP `/api/laudos?efeitos=0` → **IF prioridade = crítico** → (sim) HTTP `/api/acoes/contato-ativo` → (ambos) Respond to Webhook com o resultado. Nota atualizada.
- [x] **2.2 Fluxo 2 · Publicação.** Webhook → HTTP `/api/avisos/publicacao` → **IF status é enviado ou simulado** → (não) HTTP `/api/acoes/falha` `{origem: "aviso"}` → Respond to Webhook.
- [x] **2.3 Fluxo 3 · Dúvida.** Webhook (resposta pelo nó de resposta) → HTTP `/api/duvidas?efeitos=0` → **Switch por `tipo_final`** com 5 saídas nomeadas: `a · exame do paciente`, `b · educativa`, `c · fila de triagem`, `d · urgência` (→ HTTP `/api/acoes/urgencia`), `e · recepção` → Merge → Respond to Webhook com a `mensagem`. O serviço continua mandando a mensagem ao paciente.
- [x] **2.4 Fluxo 4 · Rotinas.** Manter agendador 8h + webhook demo → HTTP `/api/rotinas` → **IF houve alerta novo** → nó "Resumo do dia" (Set) com as contagens, para aparecer no histórico de execuções.
- [x] **2.5 Fluxo 5 · Erros (novo).** Error Trigger → HTTP `/api/acoes/falha` `{origem: nome do fluxo, detalhe: nó e mensagem}`. Nos fluxos 1–4, `settings.errorWorkflow` aponta para ele.
- [x] **2.6 Novas tentativas.** `retryOnFail` (3 tentativas, 2 s) **só** nos nós que não chamam a LLM (`/api/avisos/publicacao`, `/api/rotinas`, `/api/acoes/*`). Nos nós `/api/laudos` e `/api/duvidas`: sem nova tentativa (evita chamar a LLM duas vezes) e `timeout` de 120 s.
